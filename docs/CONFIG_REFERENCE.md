# Neovim and tmux configuration: complete reconstruction reference

> **Priority:** The checked-in files under `nvim/` and `tmux.conf` in the private dotfiles repository are the authoritative source. This document is a **reconstruction fallback** based on the configuration established in the October 2026 setup conversation. It was not generated by reading the live Fedora filesystem. In particular, plugin declarations are reconstructed from the verified design; compare with the Git repository before replacing anything. Do not overwrite a working checkout with this appendix.

## `nvim/lua/config/keymaps.lua`

```lua
local map = vim.keymap.set
map("n", "<Esc>", "<cmd>nohlsearch<CR>", { desc = "Clear search highlighting" })
map("n", "<C-h>", "<C-w>h", { desc = "Window left" })
map("n", "<C-j>", "<C-w>j", { desc = "Window down" })
map("n", "<C-k>", "<C-w>k", { desc = "Window up" })
map("n", "<C-l>", "<C-w>l", { desc = "Window right" })
map("n", "gd", vim.lsp.buf.definition, { desc = "Go to definition" })
map("n", "gr", function()
  require("telescope.builtin").lsp_references()
end, { desc = "Find references" })
map("n", "gi", vim.lsp.buf.implementation, { desc = "Go to implementation" })
map("n", "gy", vim.lsp.buf.type_definition, { desc = "Go to type definition" })
map("n", "K", vim.lsp.buf.hover, { desc = "Show documentation" })
map("n", "[d", function()
  vim.diagnostic.jump({ count = -1, float = true })
end, { desc = "Previous diagnostic" })
map("n", "]d", function()
  vim.diagnostic.jump({ count = 1, float = true })
end, { desc = "Next diagnostic" })
map("n", "<leader>e", vim.diagnostic.open_float, { desc = "Show diagnostic details" })
```

`gd`/`gi`/`gy`/`K` use Neovim's built-in LSP API; `gr` deliberately uses Telescope's references picker. These require an attached language server to be useful. `Ctrl+h/j/k/l` move **between Neovim windows**, not tmux panes. `Ctrl+o` is Vim's standard jump-back command.

## `nvim/lua/config/lazy.lua`

```lua
local lazypath = vim.fn.stdpath("data") .. "/lazy/lazy.nvim"
if not (vim.uv or vim.loop).fs_stat(lazypath) then
  local result = vim.fn.system({
    "git", "clone", "--filter=blob:none", "--branch=stable",
    "https://github.com/folke/lazy.nvim.git", lazypath,
  })
  if vim.v.shell_error ~= 0 then
    error("Failed to clone lazy.nvim: " .. result)
  end
end
vim.opt.rtp:prepend(lazypath)
require("lazy").setup({
  spec = { { import = "config.plugins" } },
  defaults = { lazy = false },
  install = { missing = true },
  checker = { enabled = false },
  change_detection = { notify = false },
})
```

This bootstraps lazy.nvim on first launch and imports all plugin spec files in `lua/config/plugins/`. **The bootstrap implementation above is a functional reconstruction**, not a byte-for-byte verified copy; prefer the tracked file. `:Lazy restore` installs revisions from `lazy-lock.json`. The bootstrap `stable` branch and the manager's locked revision are not the same concept; check the manager's version if reproducibility issues arise.

## `nvim/lua/config/plugins/editor.lua`

```lua
return {
  {
    "nvim-treesitter/nvim-treesitter",
    branch = "main",
    build = ":TSUpdate",
    lazy = false,
    config = function()
      require("nvim-treesitter").install({ "c_sharp", "lua", "json", "xml", "bash" })
      vim.api.nvim_create_autocmd("FileType", {
        pattern = { "cs", "lua", "json", "xml", "sh" },
        callback = function(args)
          local ok = pcall(vim.treesitter.start, args.buf)
          if not ok then
            vim.bo[args.buf].syntax = "on"
          end
        end,
      })
    end,
  },
}
```

Treesitter parses source code for structural highlighting; it does **not** provide definitions, diagnostics, or compilation. For C#, Neovim filetype is `cs`, Treesitter parser is `c_sharp`. Parser installation may require build tools and network access.

## `nvim/lua/config/plugins/debug.lua` — native debugger

**Status:** The live debugger was tested successfully with `debug-test` and `sis-escape-run`. The actual tracked `debug.lua` remains authoritative. The following is the **verified algorithm and key configuration fragments**, not a claim that this documentation contains a byte-for-byte snapshot of the entire live file.

```lua
local dap = require("dap")
dap.adapters.coreclr = {
  type = "executable",
  command = vim.fn.stdpath("data") .. "/mason/bin/netcoredbg",
  args = { "--interpreter=vscode" },
}

-- Inside dap.configurations.cs[1]:
program = function()
  local cwd = vim.fn.getcwd()
  local result = vim.system({
    "dotnet", "msbuild",
    "-getProperty:OutputType",
    "-getProperty:TargetPath",
    "-property:Configuration=Debug",
  }, { cwd = cwd, text = true }):wait()

  if result.code ~= 0 then
    vim.notify("MSBuild project lookup failed: " .. (result.stderr or ""), vim.log.levels.ERROR)
    return nil
  end
  local ok, data = pcall(vim.json.decode, result.stdout or "")
  if not ok or type(data) ~= "table" or type(data.Properties) ~= "table" then
    vim.notify("Unexpected MSBuild output", vim.log.levels.ERROR)
    return nil
  end
  local props = data.Properties
  if props.OutputType ~= "Exe" and props.OutputType ~= "WinExe" then
    vim.notify("Current directory is not a runnable .NET project", vim.log.levels.ERROR)
    return nil
  end
  local dll = props.TargetPath
  if type(dll) ~= "string" or vim.fn.filereadable(dll) ~= 1 then
    vim.notify("Run dotnet build -c Debug first", vim.log.levels.ERROR)
    return nil
  end
  return dll
end,
```

The actual plugin spec also declares `mfussenegger/nvim-dap`, `rcarriga/nvim-dap-ui`, and `nvim-neotest/nvim-nio`, sets breakpoint sign `●` and stopped sign `➜`, and registers `F5`, `F9`, `F10`, `F11`, `Shift+F11`, `Space db`, `Space dr`, `Space dt`, and `Space du`. `nvim-dap-ui` opens/closes with debugger sessions when its installation is complete. **Do not paste the fragment above as a whole Lua file**: it is intentionally scoped to the relevant parts of the plugin configuration. The known-good repository file is the recovery source.

**External dependency:** Mason package `netcoredbg` was tested at version `3.1.3-1`; executable `~/.local/share/nvim/mason/bin/netcoredbg`. Install it separately from the plugin lockfile, verify `netcoredbg --version`, and confirm `:Lazy` reports DAP plugins installed. `nvim-dap-ui` and `nvim-nio` directories containing only `.git` indicate incomplete checkouts; use lazy.nvim's install/restore workflow rather than editing the DAP Lua to compensate.

**Validation:** `nvim --clean --headless -n +"lua local f,e=loadfile(vim.fn.expand('~/.config/dotfiles/nvim/lua/config/plugins/debug.lua')); print(e or 'Lua syntax OK')" +qa` checks syntax only. A real `F5` launch is the integration test. See [DEBUGGING.md](DEBUGGING.md).

## `tmux.conf`

```tmux
# Personal tmux configuration
# Prefix: Ctrl+b
set -g mouse on
set -g base-index 1
setw -g pane-base-index 1
set -g renumber-windows on
set -g default-terminal "tmux-256color"
set -as terminal-features ",xterm-256color:RGB"
set -sg escape-time 10
set -g history-limit 20000
set -g pane-border-status off
set -g pane-active-border-style "fg=green"
bind | split-window -h -c "#{pane_current_path}"
bind - split-window -v -c "#{pane_current_path}"
bind c new-window -c "#{pane_current_path}"
bind r source-file ~/.config/tmux/tmux.conf \; display-message "tmux config reloaded"
```

This matches the behavior tested: `mouse on`, `base-index 1`, `default-terminal tmux-256color`; standard `Ctrl+b` then `%` / `"` also work. The active server must load the configuration (`tmux source-file ~/.config/tmux/tmux.conf`) or be restarted after linking it. Sessions persist after detach, **not after reboot**.

## Troubleshooting map

- **`:Lazy` fails:** verify Git, network, Neovim version, and plugin-manager bootstrap output.
- **Telescope grep empty:** verify `rg --version`, solution root, and ignored-file behavior.
- **Treesitter missing:** verify parser installation, filetype `cs`, and `:TSUpdate`.
- **Roslyn absent:** verify `.cs` file, Mason binary, solution path, SDK, and `:checkhealth vim.lsp`; allow indexing time.
- **Diagnostics missing:** warnings/errors are inline, other severities may not be; use `vim.diagnostic.get(0)` for diagnosis and `Space e` for details.
- **Claude edits don't show:** save/resolve local buffer changes first; use `:checktime`; don't force reload an unsaved buffer.
- **tmux settings ignored:** verify `readlink -f ~/.config/tmux/tmux.conf`, then reload and inspect `tmux show-option -g mouse`.
